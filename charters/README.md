# charters/ — 노드 문서 3종과 그 역할

이 폴더에는 **템플릿**과 **예시 트리**가 들어있다.

| 파일 | 무엇 |
|---|---|
| `charter-template.md` | 빈 charter 스켈레톤. 노드를 새로 만들 때 복사한다. |
| `examples/` | `control/tree.config.json`이 가리키는 **바로 돌려볼 수 있는 예시 트리**(가상의 SaaS 제품 "Acme App"). 자기 것으로 바꾸기 전에 CLI를 시험해 보는 용도. |
| `examples/channels/01-backend.md` | **잘 쓴 charter의 예.** 어느 정도 구체적으로 써야 하는지 감을 잡는 용도. |

## 노드 하나에 붙는 파일 3종

세션은 언제든 죽거나 아카이브된다. **대화가 아니라 파일이 진실**이어야 새 세션이
맥락을 복원할 수 있다. 그래서 노드마다 성격이 다른 문서 3개를 둔다.

```
charters/examples/channels/
├── 01-backend.md              ← charter    : 지금 상태 (덮어쓰며 유지)
├── 01-backend.log.md          ← log        : 흐름   (append-only, 지우지 않음)
└── 01-backend-releases.md     ← releases   : 학습   (버전별, 최신이 위)
```

### 1. charter — "지금 상태" (pinned)

- **성격:** 계속 **고쳐 쓴다.** 낡은 문장은 지운다. 항상 현재를 반영한다.
- **읽는 시점:** 세션을 열 때 **가장 먼저**. 이 파일만 읽고도 일을 이어받을 수 있어야 한다.
- **들어가는 것:** 목표 / 범위 / 열린 질문 / 결정된 것 / 다음 행동 / 세션 로그(요약).
- **분량:** A4 2장 안쪽을 목표로. 넘치면 결론만 남기고 과정은 log로 내린다.
- **안 들어가는 것:** 진행 과정의 시시콜콜함, 다른 레벨의 논의.

### 2. log — "흐름" (append-only)

- **성격:** **지우지 않는다.** 한 줄씩 덧붙이기만 한다.
- **왜:** charter는 계속 덮어써지므로 "어쩌다 여기까지 왔는지"가 사라진다. 그 궤적을 남긴다.
- **쓰는 법:** `python3 control/node.py log L5.1 "결정: 큐를 Redis 대신 Postgres로"`
- **읽는 시점:** charter를 읽고도 "왜 이렇게 됐지?"가 남을 때만. 매번 읽을 필요 없다.

### 3. releases — "학습 자료" (versioned)

- **성격:** 실질적 변경에만 버전을 붙여 쌓는다. **최신이 맨 위.**
- **왜:** 변경 이력이 아니라 **학습 자료**다. 비슷한 걸 다시 만들 때 참고하고, 과거 실패가
  사라지지 않게 한다. 그래서 "무엇을 바꿨다"만 쓰면 목적의 절반을 놓친다.
- **쓰는 법:**
  ```bash
  python3 control/node.py note L5.1 0.3.0 \
    --changed "업로드 API에 멱등키(Idempotency-Key) 요구" \
    --why     "재시도 때 중복 생성되는 사고를 막으려고" \
    --problem "2026-06-11 클라이언트 재시도로 주문 3건 중복 생성" \
    --lesson  "쓰기 API는 처음부터 멱등성 계약을 명시한다"
  ```
- **읽는 시점:** 같은 영역을 다시 손대기 직전. "여기서 예전에 뭐가 터졌나"를 확인.

## 어디에 쓸지 헷갈릴 때

| 쓰려는 내용 | 어디 |
|---|---|
| "지금 무슨 문제를 풀고 있나" | charter · 현재 상태 |
| "이건 아직 못 정했다" | charter · 열린 질문 |
| "A로 가기로 했다(2026-07-25)" | charter · 결정된 것 (+ log에 한 줄) |
| "다음에 이걸 해야 한다" | charter · 다음 행동 `- [ ]` |
| "오늘 세션에서 이런 대화가 오갔다" | log |
| "이 부분을 이렇게 바꿨고, 직전엔 이게 문제였다" | releases (`note`) |
| "다른 노드가 이걸 해줬으면 한다" | 우편함 (`handoff`) — 문서가 아니다 |

> `- [ ]` 체크박스 형식은 지켜라. 스탠드업 스크립트와 헤드리스 디스패처가 charter의
> 「다음 행동」과 우편함을 이 형식으로 스캔한다.
