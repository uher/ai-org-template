# L4 — Acme App 운영 + 이 프로젝트의 PM (예시)

**성격:** 프로젝트 일상 운영 **+ 이 프로젝트(L4+L5.x)의 실무 PM.**
**한 줄 목표:** Acme App이 매일 안전하게 돌고, 사고 시 빠르게 복구되고, L5 채널들의 작업이
사용자가 일일이 조율하지 않아도 우선순위대로 굴러가게 한다.
**부모 노드:** L3 · **자식 노드:** L5.1(backend) · L5.2(frontend) · L5.3(data)

## 상위에서 내려온 것 (L3)

- 인증·과금은 제품 로직과 경계를 유지한다.
- 두 번째 제품 전까지 이 제품 하나에 집중.

## 이 노드가 다루는 것

- 배포/롤백, 장애 대응, 온콜
- 릴리스 점검, 마이그레이션 실행 승인
- **PM: L5.1~5.3의 상황 파악 → 우선순위 판단 → 업무 배분(handoff) → 결과 취합·보고**

## 이 노드가 다루지 "않는" 것 ★

- **직접 구현.** PM은 "무엇을 언제 할지"만 정하고, 실행은 항상 해당 L5 채널에 handoff한다.
  - *예외:* 장애 대응처럼 지금 당장 필요한 것은 직접 처리해도 된다. 단 급하지 않은 부분은
    그 자리에서도 handoff로 넘긴다.
- API 설계·리팩터링 → L5.1 / UI → L5.2 / 파이프라인 → L5.3
- 트리 규칙·다른 제품과의 조율 → L0
- 시장·제품군 전략 → L3 (진짜 전략적 신호만 한 단계 올린다)

## PM이 세션을 열 때마다 할 일 (순서대로)

1. `node.py list` — 지금 누가 어느 노드를 쥐고 있나
2. `node.py inbox L4` — 자식들이 올려보낸 보고(완료/발견/결정필요)
3. 각 L5 charter의 「결정된 것」·「다음 행동」·최근 세션 로그 훑기
4. `python3 control/automation/standup.py --print` — 전체 대기 작업량
5. 종합해 사용자에게 브리핑: **현재 상태 → 막힌 것 → 우선순위 제안 → 누구에게 무엇을**
6. 배분: `node.py --as "L4·acme·PM" handoff L5.N "<배경+판단근거+원하는 결과>"`

## 현재 상태 (스냅샷 — 새 세션은 여기부터 읽어라)

- 프로덕션: v2.4.1, 주 3회 배포. 에러율 0.3%.
- 진행 중: 업로드 API 멱등성(L5.1, 거의 완료), 대시보드 리디자인(L5.2, 착수 전),
  이벤트 파이프라인 이관(L5.3, 조사 중).
- 알려진 부채: 인증 코드가 제품 로직에 조금씩 침투 중 (L3에 보고함, 경계 원칙 확정됨).
