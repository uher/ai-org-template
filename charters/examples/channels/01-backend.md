# L5.1 — backend (Acme App API·서버)

**성격:** 논의 + 구현
**한 줄 목표:** API가 재시도·중복 요청·부분 장애에서도 **예측 가능하게** 동작하게 만든다.
**부모 노드:** L4 (acme-app·PM) — 완료/발견/결정필요는 여기로 handoff.

## 상위에서 내려온 것 (L4)

- 인증·과금 코드는 제품 로직과 경계를 유지한다(L3 결정).
- DB를 직접 고치는 스크립트는 백업 + 변경 로그 필수.
- 배포는 금요일 오후 금지.

## 목표 (왜 이 채널인가)

프런트엔드·데이터 파이프라인·외부 연동이 전부 이 API에 붙는다. 여기서 계약이 흔들리면
다른 채널이 전부 흔들린다. 그래서 이 채널의 결론은 **"동작한다"가 아니라 "계약이 명시됐다"**
여야 한다.

## 이 채널이 다루는 것 / 다루지 않는 것

- 다룬다: HTTP API 계약, 도메인 로직, DB 스키마/마이그레이션, 백그라운드 잡
- 다루지 않는다:
  - UI·클라이언트 상태 관리 → **L5.2 frontend**
  - 이벤트 수집/집계 파이프라인 → **L5.3 data**
  - 배포 시점·릴리스 판단 → **L4** (PM)

## 현재 상태

- 핵심 엔드포인트 24개 중 쓰기 12개. 그중 **멱등키를 요구하는 것은 8개**(진행 중).
- 마이그레이션은 수동 승인 후 실행. 자동 롤백 없음(알려진 한계).
- 통합 테스트는 있으나 재시도/중복 시나리오 커버리지가 얕다.
