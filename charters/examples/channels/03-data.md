# L5.3 — data (이벤트 수집·집계 파이프라인)

**성격:** 논의 + 구현
**한 줄 목표:** 제품 이벤트를 잃지 않고 모아, 하루 단위 지표를 신뢰할 수 있게 만든다.
**부모 노드:** L4 (acme-app·PM)

## 상위에서 내려온 것 (L4)

- 데이터 보정 스크립트는 백업 + 변경 로그 필수.
- 지표를 보고할 때는 "원천 수치"와 "가공 수치"를 같이 적는다(한쪽만 쓰지 않는다).

## 목표

수집 → 저장 → 집계의 각 단계에서 유실·중복을 **측정 가능하게** 만든다. 측정 안 되는
파이프라인은 신뢰할 수 없다.

## 현재 상태

- 조사 중. 현재는 앱 서버가 직접 집계 테이블에 쓴다(장애 시 조용히 유실).

## 열린 질문

1. 큐를 도입할 가치가 있나? 지금 트래픽에서 과한 인프라 아닌가?
2. 유실률을 어떻게 측정하나 — 발신 측 카운터 vs 수신 측 카운터의 대사(reconciliation)?
