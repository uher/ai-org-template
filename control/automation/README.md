# control/automation/ — 선택 기능 (없어도 시스템은 완전히 돌아간다)

여기 있는 것들은 **전부 선택**이다. 트리·락·우편함·릴리스 노트만으로 시스템은 완성돼
있고, 이 폴더는 "사람이 세션을 여는 것"을 덜 잊게 도와줄 뿐이다. 처음 도입할 때는
건너뛰고, 손으로 쓰다가 불편해지면 그때 붙여라.

| 파일 | 무엇 | 위험도 |
|---|---|---|
| `standup.py` | 모든 노드의 우편함 + charter 「다음 행동」을 모아 한 장으로. | 읽기 전용, 안전 |
| `backlog-dispatcher.sh` | 헤드리스 AI 세션을 깨워 백로그 1건을 처리시킨다. | **높음 — 아래 참고** |
| `prompts/backlog-dispatcher.md` | 그 헤드리스 세션에 주는 지시문(범위 제한 포함). | — |
| `com.example.tree-dispatcher.plist` | macOS launchd 등록 예시(경로 치환 필요). | — |
| `crontab.example` | Linux/WSL 대안. | — |

## standup — 먼저 이것만 써봐라

```bash
python3 control/automation/standup.py --print     # 출력만
python3 control/automation/standup.py             # + 텔레그램(notify 설정 시)
```

`- [ ]` 체크박스와 우편함을 스캔한다. 매일 아침 한 번 돌리면 "오늘 어느 세션을 열어야
하는지"가 정리된다. 이것만으로도 여러 채널 운영의 체감 부담이 크게 준다.

## 헤드리스 디스패처 — 도입 전에 반드시 읽을 것

세션은 데몬이 아니다. 누가 턴을 줘야 깨어난다. 그래서 우편함에 일이 쌓여도 사람이 그
세션을 열지 않으면 그대로 있다. 디스패처는 OS 스케줄러가 **새 비대화식 세션**을 띄워
그 갭을 메우는 장치다.

**실전에서 얻은 규칙 (그대로 지키길 권함):**

1. **자동화 허용 노드를 명시적으로 좁혀라.** 기준은 "실패했을 때 진짜 돈·사용자·외부
   커뮤니케이션에 즉시 영향이 가는가". 가면 자동화 금지, 안 가면 허용.
   설계·분석·문서 작업(하위 채널)은 대체로 허용, 운영/대외 노드는 항상 수동.
2. **한 번에 하나만 처리.** 예산·시간 상한이 있고, 사람이 검토 가능한 단위여야 한다.
3. **승인 게이트를 끄지 마라.** 애매한 행동은 승인 대기에 걸려 그 턴이 실패하는 게
   맞다 — 사람이 없을 때의 안전한 기본값은 "아무것도 안 함"이다(fail-closed).
4. **AI가 자기 권한을 스스로 넓히게 하지 마라.** 권한 설정 파일 작성, `chmod +x`,
   승인 우회 플래그는 **사람이 직접** 한다. (실전에서 반복 확인된 함정이다.)
5. **락을 존중하게 하라.** 이미 잡힌 노드는 건너뛴다. 사람이 그 세션에서 작업 중일 수 있다.
6. **결과는 반드시 부모 노드 우편함으로 보고**하게 한다. 로그 파일만 남기면 아무도 안 본다.
7. 헤드리스 실행은 **기억이 없다.** 매번 charter/우편함에서 맥락을 다시 읽는다 —
   이 시스템이 파일 기반인 이유가 여기서 다시 확인된다.

설치 절차는 `../../SETUP.md` 「선택 3: 헤드리스 디스패처」 참조.
