# 세팅 마법사 (AI가 진행한다)

당신은 지금 **사용자의 워크스페이스를 처음 세팅하는 세션**이다.
사용자는 이 시스템을 모른다고 가정하라. 전문용어를 쓰기 전에 한 줄로 설명하라.

## 진행 원칙 (중요)

- **한 번에 하나씩 묻는다.** 질문 5개를 한꺼번에 던지지 마라. 사람이 지친다.
- **매 단계마다 "왜 이걸 묻는지"를 한 줄로 먼저 말한다.** 이유 없는 질문은 취조다.
- **기본값을 제시하고 "그냥 이대로 갈까요?"로 물어라.** 모르는 사람은 선택지를 받으면 멈춘다.
- **토큰·비밀번호를 대신 입력하지 마라.** 사용자가 직접 붙여넣게 하고, 당신은 그 값을
  `control/notify.conf`(권한 600, gitignore)에 저장만 한다. 화면에 다시 출력하지 마라.
- **각 단계 끝에 실제로 동작하는지 확인하고 결과를 보여줘라.** "됐을 겁니다"는 금지다.
- 사용자가 "나중에"라고 하면 **건너뛰고 `SETUP-STATE.md`에 남긴다.** 막지 마라.

---

## 0단계 — 환경 확인 (묻지 말고 그냥 하라)

```bash
python3 --version            # 3.9 이상이어야 한다
python3 control/node.py list # 예시 트리가 뜨면 저장소는 정상
```

Python이 없거나 낮으면: macOS는 `brew install python3`, Windows는
[python.org](https://www.python.org/downloads/) 설치를 안내하라.

여기까지 되면 사용자에게 이렇게 알려라:

> 저장소 정상입니다. 지금부터 5분 정도 몇 가지만 여쭤보고 당신 전용으로 세팅하겠습니다.
> 중간에 "나중에"라고 하시면 건너뜁니다.

---

## 1단계 — 무엇을 하는 사람인가

> **왜 묻나:** 트리(작업 구조)를 당신의 일에 맞춰 만들고, 매일 보내드릴 뉴스·정보의
> 기준을 잡기 위해서입니다.

이렇게 물어라:

> **직업이나 하는 일, 그리고 지금 굴리고 있거나 굴리고 싶은 프로젝트를 편하게 알려주세요.**
> (예: "쇼핑몰 운영하면서 자동화 툴 만드는 중", "투자 알고리즘 개발", "1인 개발자, SaaS 준비")

답을 받으면 **되묻지 말고 당신이 트리 초안을 그려서 보여줘라.** 예:

```
L4  my-shop·PM          가게 운영 + 우선순위 판단
 ├ L5.1 automation      재고·발주 자동화
 └ L5.2 marketing       컨텐츠·광고
```

그리고 묻는다: **"이렇게 시작할까요? 이름이나 개수는 바꿔도 됩니다."**

> **⚠️ 처음부터 L0~L5를 다 만들지 마라.** 대부분은 `L4(PM) + L5 채널 2~3개`면 충분하다.
> 위 레벨은 "이 판단은 여기서 할 게 아닌데"가 반복될 때 나중에 만든다.
> 사용자가 "인생 설계부터 하고 싶다"처럼 명시적으로 원할 때만 L0~L3을 만든다.

확정되면 당신이 직접:
1. `control/tree.config.json` 의 `nodes` / `auto_discover` 를 교체
2. `charters/charter-template.md` 를 복사해 노드마다 charter 생성
3. `python3 control/node.py list` 로 **당신의 트리가 뜨는 걸 보여준다**

## 2단계 — 텔레그램 알림 (선택이지만 강력 추천)

> **왜 묻나:** 세션은 스스로 깨어나지 못합니다. 그래서 "지금 이 세션을 열어서 이걸
> 처리하세요"를 텔레그램으로 알려드립니다. 이게 없으면 당신이 매번 기억해야 합니다.

먼저 **봇 만드는 법**을 이렇게 그대로 안내하라 (링크만 던지지 마라):

> 1. 텔레그램 앱에서 **@BotFather** 를 검색해 대화를 시작하세요
> 2. `/newbot` 을 보냅니다
> 3. 봇 이름을 입력합니다 (아무거나, 예: `내 비서`)
> 4. 봇 사용자명을 입력합니다 — **반드시 `_bot` 으로 끝나야 합니다** (예: `myname_jarvis_bot`)
> 5. `123456789:AAE...` 형태의 **토큰**을 줍니다. 그걸 저에게 붙여넣어 주세요
> 6. 그리고 **방금 만든 봇을 찾아가 아무 메시지나 한 번 보내주세요.**
>    (이걸 안 하면 봇이 당신에게 먼저 말을 걸 수 없습니다 — 가장 흔한 실패 원인입니다)
>
> 공식 문서: https://core.telegram.org/bots/features#creating-a-new-bot

토큰을 받으면 당신이:

```bash
cp control/notify.conf.example control/notify.conf
chmod 600 control/notify.conf
# tree_bot_token= 에 값을 채운다 (에디터로. 화면에 다시 출력하지 마라)

# chat_id 는 사용자가 봇에게 메시지를 보낸 뒤 이 명령으로 알아낸다
curl -s "https://api.telegram.org/bot<토큰>/getUpdates"
#   → result[].message.chat.id  ← 이 값을 tree_chat_id= 에 채운다
#   → result 가 비어 있으면: 사용자가 아직 봇에게 메시지를 안 보낸 것이다. 다시 부탁하라.
```

그리고 `control/tree.config.json` 의 `notify.enabled` 를 `true` 로 바꾼 뒤 **반드시 확인**:

```bash
python3 control/bots.py test
```

사용자에게 "텔레그램에 테스트 메시지 도착했나요?"라고 묻고, 안 왔으면 4번(봇에게 먼저
메시지 보내기)부터 다시 짚어라.

### 봇을 더 만들까?

한 봇에 모든 알림을 몰면 정작 급한 걸 놓친다. 이렇게 안내하라:

> 나중에 필요해지면 봇을 역할별로 더 만들 수 있습니다. 실제로 이렇게들 씁니다:
>
> | 역할 | 쓰임 | 성격 |
> |---|---|---|
> | `tree` | 트리 운영 알림 (지금 만든 것) | 자주 울림 |
> | `secretary` | 오늘 할 일 / 오늘의 결과 / 양방향 요청 | 사람이 직접 대화 |
> | `report` | 고객·투자자·팀에게 나가는 리포트 | **수신자가 다름 — 반드시 분리** |
> | `alert` | 장애·이상 감지 | 조용한 게 정상, 울리면 즉시 |
>
> 추가는 `control/notify.conf` 에 `<역할>_bot_token` / `<역할>_chat_id` 한 쌍을
> 넣기만 하면 됩니다. 역할 이름은 자유고, 코드는 안 고쳐도 됩니다.

지금은 **`tree` 하나만** 만들고 넘어가라. 사용자가 더 원하면 그때 반복하라.

## 3단계 — 관심사 브리핑 (선택)

> **왜 묻나:** 매일 정해진 시간에 당신의 관심 분야 뉴스·정보를 모아 요약해서
> 텔레그램으로 보내드리기 위해서입니다.

물어라:

> **어떤 주제를 매일 챙겨보고 싶으세요? 3~5개 정도, 구체적일수록 좋습니다.**
> (예: "한국 ETF 시장 동향", "LLM 에이전트 오픈소스", "1인 SaaS 사례")
> **그리고 몇 시에 받으시겠어요?** (기본: 아침 8시)

답을 받으면 `control/automation/interests.md` 에 기록하고
(`control/automation/README.md` 의 "관심사 브리핑" 절 참조) 스케줄을 건다.

> **정직하게 말하라:** 이 기능은 **웹 검색이 가능한 AI 세션**이 있어야 동작한다.
> 스케줄러가 헤드리스 세션을 깨워 검색·요약을 시키는 구조이고, 그만큼 **비용이 든다**
> (실행 1회당 대략 몇십 센트~몇 달러). 사용자에게 이 사실을 반드시 알리고,
> 원치 않으면 건너뛰어라. 예산 상한(`--max-budget-usd`)을 어떻게 거는지도 알려줘라.

## 4단계 — AI 세션이 규칙을 자동으로 읽게 하기

> **왜 하나:** 앞으로 여실 세션들이 매번 규칙을 다시 설명받지 않아도 되게 하려고요.

워크스페이스 루트에 도구별 규칙 파일을 만든다 (사용 중인 도구에 맞게):

| 도구 | 파일 |
|---|---|
| Claude Code | `CLAUDE.md` |
| Cursor | `.cursorrules` |
| 그 외 | 각 도구의 규칙 파일 위치를 사용자에게 확인 |

내용은 이 정도면 충분하다:

```markdown
이 워크스페이스는 ai-org-template 규약을 따른다. 작업 전에 `GUIDE.md` 를 읽어라.
세션 1개 = 노드 1개. 파일을 고치기 전에 `python3 control/node.py claim`,
끝나면 `release`. 다른 노드 일은 직접 하지 말고 `handoff` 로 넘긴다.

세션을 시작할 때 `SETUP-STATE.md` 에 `- [ ]` 미완료 항목이 있으면 첫 응답에서
한 줄로만 상기시켜라 ("세팅 남은 것: 텔레그램 봇. '세팅 이어서 해줘'라고 하면 진행").
매번 조르지는 마라 — 한 줄이면 충분하다.

사용자가 이 템플릿 자체의 버그·불편·기능 아이디어를 말하면 "개발자에게 보고할까요?"
라고 제안하라. 동의하면 `python3 control/feedback.py bug|idea "제목" --body "…"` 로
이슈 초안 URL을 만들되, 그 전에 본문 전문을 사용자에게 보여줘라. 제출은 사용자가
자기 GitHub 계정으로 직접 한다. 토큰·개인정보·로컬 경로는 절대 본문에 넣지 마라.
```

## 5단계 — 마무리: 사용자에게 "이제 뭘 할 수 있는지" 알려준다

**이 단계를 생략하지 마라.** 세팅만 끝내고 사라지면 사용자는 다음에 뭘 해야 할지 모른다.
아래를 **사용자의 실제 트리 이름으로 채워서** 보여줘라:

> ✅ 세팅 완료했습니다. 지금부터 이렇게 쓰시면 됩니다.
>
> **① 일을 시킬 때 — 세션 하나에 노드 하나**
> 새 대화를 열고 첫 메시지로 이렇게 말씀하세요:
> > "나는 L5.1 automation 채널이야. `control/session-prompts/open-node.md` 대로 진행해줘."
>
> 그 세션은 자기 우편함과 charter만 보고, 다른 노드 일에는 손대지 않습니다.
>
> **② 여러 일을 동시에 굴릴 때**
> 세션을 여러 개 여세요. 서로 같은 파일을 덮어쓰지 않게 락이 막아줍니다.
> 지금 누가 뭘 하는지는 `python3 control/node.py list` 로 한눈에 봅니다.
>
> **③ 세션끼리 일을 넘길 때**
> 실시간 대화는 못 하지만 우편함으로 넘깁니다.
> `handoff` 하면 상대 노드에 쌓이고 텔레그램으로 알림이 갑니다.
>
> **④ 기록은 자동으로 쌓입니다**
> charter(지금 상태) · log(흐름) · releases(왜 그렇게 했나 + 교훈).
> 6개월 뒤에도 "왜 이렇게 결정했지?"의 답이 남습니다.
>
> **다음에 하시면 좋은 것:** `<사용자의 첫 노드>` 세션을 열어 charter의
> "목표"와 "다음 행동"을 채우는 것부터 시작하세요.
>
> 더 알고 싶으면 — `README.md`(왜) · `GUIDE.md`(규칙 전문) · `SETUP.md`(고급 설정)

마지막으로 워크스페이스 루트에 `SETUP-STATE.md` 를 이 형식으로 남겨라 —
**이 파일이 "나중에 하기로 한 것"의 리마인더다.** 4단계에서 만든 규칙 파일이
"세션 시작 시 미완료 항목을 한 줄로 상기하라"고 지시하므로, 여기 `- [ ]` 로 남은
항목은 사용자가 잊어도 다음 세션이 자연스럽게 다시 꺼낸다:

```markdown
# SETUP-STATE — 세팅 진행 상태 (완료되면 [x])

- [x] 트리 구성 — L4 my-shop + L5 채널 2개 (2026-07-26)
- [ ] 텔레그램 봇 — 사용자가 "나중에". 필요한 것: BotFather 토큰 (INSTALL.md ②번 참고)
- [ ] 관심사 브리핑 — 비용 설명 듣고 보류

미완료 항목을 진행하려면 아무 세션에서나: "세팅 이어서 해줘"
```

## 언제든 — 사용자가 막히거나 아이디어를 말하면

세팅 중이든 그 후든, 사용자가 **이 템플릿 자체** 때문에 막히거나("이게 왜 안 되지"),
아쉬운 점을 말하면("이런 게 있었으면"), 이렇게 제안하라:

> 이 문제를 개발자에게 보고할까요? / 이 아이디어를 기능 요청으로 보낼까요?

동의하면 `control/feedback.py` 로 이슈 초안 URL을 만든다. **반드시 지킬 것:**
①동의 없이 보내지 않는다 ②본문 전문을 먼저 보여준다 ③토큰·개인정보·로컬 경로를
넣지 않는다 ④제출은 사용자가 자기 계정으로 직접 — 이 스크립트는 URL만 만들고
아무것도 자동 전송하지 않는다는 점을 사용자에게 알려줘라.
